## Initial code findings

Inspected at `0f8fcd72` plus unrelated uncommitted browser verification work:

- `web/src/lib/symbolsweep.ts`: `transformsFor` enumerates quarter-turn rotations and optional reflection. `matchSymbol` applies a stated scalar scale ratio; it does not estimate arbitrary affine transforms. It already uses rare-length segment anchors, cached endpoint/length indexes, junction anchors for split strokes, oriented line-body coverage, near-match reporting, explicit counterexamples, and candidate-ceiling disclosure. Preserve these features rather than recreating them.
- `web/src/lib/legendlearn.ts`: legend discovery is distinct from plan matching; glyphs require plan-anchor/scale corroboration, and routed-system swatches are not discrete-device counts.
- `mcp/src/session.ts`: `symbolSweep` and `sweepScheduleRow` consume the shared matcher; the latter also performs tagged-view and cross-discipline room-view deduplication. This path needs a deeper scoping audit before any new quantity claims.
- `web/src/lib/schedulePlanReconcile.mjs`: `classifyReconcileStatus` currently labels a resolved positive installed quantity greater than or equal to a positive scheduled quantity `MATCH`. Audit whether that label hides overruns for each caller; this is a research finding, not an implemented fix or a demonstrated end-to-end defect.
- Existing tests include `symbolsweep`, `sweepNegative`, `sweepCoalesce`, `sweepScheduleRow`, `legendlearn`, and `schedulePlanReconcile`, plus public MCP reconciliation fixtures. Existing coverage does not establish affine/deformation performance.

## Primary-source leads and preliminary interpretation

1. Wolfson and Rigoutsos, **Geometric Hashing: An Overview**, IEEE Computational Science & Engineering, 1997. [Original paper, university-hosted copy](https://graphics.stanford.edu/courses/cs164-09-spring/Handouts/paper_geohash.pdf). Describes indexed geometric correspondences, partial information, and similarity/affine settings; also identifies uneven hash occupancy as a performance problem. **Inference:** sparse local bases may be worth benchmarking for candidate generation. Full-sheet basis enumeration is not automatically fast. Article sections and experimental limits still need complete review.
2. Rusiñol and Lladós, **Symbol Spotting in Technical Drawings Using Vectorial Signatures**. [Author-hosted paper](https://marcalr.github.io/pdfs/GREC06.pdf). Uses segment relationships and multiscale structure to identify likely regions, expressly separating spotting from subsequent recognition. Its small-subgraph enumeration also carries combinatorial cost. **Inference:** use limited local descriptors as retrieval hints, not quantity authority; rotation/scale robustness does not establish arbitrary-stretch robustness. Publication year needs bibliographic confirmation before the final report.
3. Dutta, Lladós and Pal, **A symbol spotting approach in graphical documents by hashing serialized graphs**, Pattern Recognition 46(3), 752–768, 2013. [Author publication record and paper link](https://sites.google.com/site/2adutta/publications). Follow-up to graph-path hashing at ICDAR 2011. Author-hosted download did not resolve through the research browser; full-text algorithm, performance and code-license review remains pending. Do not treat inaccessible details as verified.
4. Belongie, Malik and Puzicha, **Shape Matching and Object Recognition Using Shape Contexts**, TPAMI 24(4), 509–522, 2002. [Author-institution record](https://vision.ucsd.edu/publications/2002/shape-matching-and-object-recognition-using-shape-contexts), [earlier 2000 primary paper](https://proceedings.neurips.cc/paper_files/paper/2000/file/c44799b04a1c72e3c8593a53e8000c78-Paper.pdf). Point correspondences and aligning transforms are a different approach from fixed endpoint matching. **Inference:** expensive flexible alignment belongs, if anywhere, after bounded retrieval; flexibility can erase small but meaningful symbol differences. No BAS speed/accuracy claim is established.
5. OpenCV, **Camera Calibration and 3D Reconstruction**, version 4.11. [Official API reference](https://docs.opencv.org/4.11.0/d9/d0c/group__calib3d.html). `estimateAffinePartial2D` is a four-degree-of-freedom transform with uniform scale, not a solution to anisotropic stretch. `estimateAffine2D` estimates the fuller affine transform between correspondences. **Inference:** a benchmark must distinguish those models and reject degenerate/implausible alignments; naming an API does not solve correspondence discovery. No dependency installation authorized or performed here.
6. Open3D, **ICP registration**. [Official tutorial](https://www.open3d.org/docs/latest/tutorial/pipelines/icp_registration.html). ICP refines an approximate initial alignment; the tutorial obtains that alignment separately. **Inference:** it is not a whole-blueprint symbol locator by itself. This is a 3D example, not evidence that its implementation fits this 2D browser pipeline.
7. SciPy, **KDTree** and **query**. [Official index reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.KDTree.html), [query reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.KDTree.query.html). Documents distance-bounded and approximate nearest-neighbor searches, mutable-data hazards, and poor high-dimensional behavior. **Inference:** first measure the existing 2D indexes; a new index is not necessarily faster, and approximate retrieval can miss valid candidates. Package version and licenses must be pinned if considered later.
8. Fan et al., **FloorPlanCAD: A Large-Scale CAD Drawing Dataset for Panoptic Symbol Spotting**, ICCV 2021. [Original conference publication](https://openaccess.thecvf.com/content/ICCV2021/html/Fan_FloorPlanCAD_A_Large-Scale_CAD_Drawing_Dataset_for_Panoptic_Symbol_Spotting_ICCV_2021_paper.html). Uses vector drawings and line-grained annotations, with a trained CNN/GCN baseline. **Inference:** useful evaluation concepts, not an in-scope no-training implementation or a BAS-specific performance guarantee. No new dataset downloaded.
9. Bluebeam, **Align PDFs with Overlay Pages in Revu 20**. [Official workflow](https://support.bluebeam.com/revu/features/align-pdfs-with-overlay-pages.html). Documents alignment of differently sized/scaled drawings by corresponding points. **Inference:** a reviewable correspondence workflow is useful when automated pairing is uncertain. Alignment alone does not prove two depicted devices are the same physical instance. Documentation inspected; no hands-on competitor testing claimed.
