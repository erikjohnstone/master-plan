BUG FOUND + FIXED IN THE EVAL HARNESS (not the engine; mcp/scripts only)
  mcp/scripts/symbol-sweep-corpus.mjs's `options.affine === false` per-case
  escape hatch (8 of 47 cases: 01, 05, 06, 10, 11, 14, 18, 23) was a dead
  branch. It sent {} instead of {affine:{enabled:false}}, and
  Session.symbolSweep's own default (opts.affine ?? affineOptionsFromWire(
  AFFINE_WIRE_DEFAULT)) silently substituted the exact same affine-ON value
  the OTHER branch sends explicitly. Verified empirically on two cases
  (01-cherry-mh111-cd1, 10-lovell-m100-cd1-ceiling-diffusers) before fixing:
  the "disabled" branch, an explicit {affine:{enabled:false}}, and the
  explicit default produced byte-identical match positions. These 8 cases
  have been running with affine ON this whole time, contrary to every prior
  doc describing them as rigid-only. Fixed in the same commit that added
  the --mode flag; no web/src/lib production code touched.

SHARED-PATH PARITY -- confirmed by direct code inspection, not doc trust
Four independent call sites reference the IDENTICAL default expression
(affineOptionsFromWire(AFFINE_WIRE_DEFAULT)):
  - mcp/src/session.ts Session.symbolSweep's own internal default
  - this corpus runner's explicit default
  - web/src/pages/TakeoffCanvas.jsx's manual-marquee runSymbolSweep
  - web/src/pages/TakeoffCanvas.jsx's Agent-bridge agentSweep
One default, not four copies to drift. mcp/src/tools.ts's MCP wire schema
has a documented, PRE-EXISTING nested-zod-default gap (an explicit, empty
`affine: {}` disables affine via the inner field's own default; omitting
the key -- the common real-agent case -- gets the correct on-by-default
value). Reproduced live with a standalone zod parse test against the tool's
real schema shape. Not a new finding; not changed here.
